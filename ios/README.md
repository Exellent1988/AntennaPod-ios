# ios/ — AntennaPod for iOS

Fork-only SwiftUI shell. Playback via AVFoundation; networking/downloads via URLSession; persistence in-memory for now (SQLite later). Shared KMP parser is validated in `shared/kmp`; the iOS app currently uses a Foundation `XMLParser` fallback with the same golden fixtures in mind. Wiring the XCFramework into the app is the next integration step.

## Parental controls

Beta MVP under Settings → **Parental controls**:

- **Enable** prompts for a 4–6 digit PIN (confirm); stored in Keychain only (not UserDefaults / not backup ZIP).
- **Options:** Lock Add / Discover (PIN before Add sheet or Discover charts); optional lock Network / Downloads Wi‑Fi toggles; optional hide explicit top charts (`explicit=false` on iTunes RSS while enabled).
- **Session unlock:** correct PIN unlocks until the app backgrounds (`scenePhase` inactive/background), then gated UI asks again.
- **Disable:** requires PIN, then clears Keychain and turns options off.

Not a full device parental lock / Screen Time substitute.

## Statistics

**Subscriptions → Library → Statistics** (also **Settings → Library → Statistics**). Derived from existing `playback.json` — no separate cumulative `listenedSeconds` counter in this beta.

- **Time range** — segmented **This week / This month / This year / All time** (default). Pref `AppSettings.statisticsTimeRange` (UserDefaults + JSON backup); **shared with Echo**. Device calendar (`Calendar.current`). Filter key: `lastPlayedAtEpochMs` else `updatedAtEpochMs` (same honesty as History / Echo), **and** after any **Reset** baseline. **Coarse episode-level stamps** — not per-session listen windows; an episode last touched in-range counts its full estimate for that range.
- **Played episodes** — count of episodes with `isPlayed` in range (after Reset baseline when set).
- **In progress** — episodes with progress (`positionSeconds > 1`) that are not marked played (shown when non-zero), in range.
- **Approx. listening time** — **wall-clock** sum of estimates: **played** use saved `durationSeconds` (position cleared on mark-played); **in-progress** use `positionSeconds`. **Not speed-adjusted** (1.5× does not shrink totals). Does **not** count rewinds, re-listens, or **streaming with no saved progress**; played with **unknown duration → 0**. History size limit may drop oldest entries (and their stats).
- **Since when** — whatever remains in `playback.json` since first saved progress, or since the last **Reset statistics** baseline (`statisticsResetAtEpochMs`, UserDefaults + backup). Footnote shows the baseline date when set.
- **Top podcasts** — per-feed rollup sorted by approximate time, then play count; **same wall-clock estimate as Totals**. Queue-only episodes without a known feed count in Totals but may omit a row.
- **Share** — toolbar ⋯ → `ShareLink` plain-text summary when there is data (range, counts, approx time, top podcasts, honesty footnote). **No charts or images**.
- **Reset statistics** — toolbar ⋯ → confirm; sets baseline to now so Statistics **and Echo** only count stamps after that moment. **Does not** clear History, progress, played flags, downloads, queue, or favorites (unlike wiping History). Honest: no Android-style separate `played_duration` counter — this filters stamps.

Empty states: never any playback data; data exists but only before Reset; or none in the selected time range. EN/DE + VoiceOver on totals, per-feed rows, empty copy, and actions.

## Sleep timer volume fade

Settings → Playback **Sleep timer volume fade** (`sleepTimerFadeEnabled`, default **on**). For a **clock** sleep timer only, in the last ~10 seconds before expiry `PlaybackService` linearly lowers `AVPlayer.volume` toward 0 (Android `SleepTimer.NOTIFICATION_THRESHOLD`). On fire, playback pauses as today and volume is restored to the pre-fade level (Volume boost remains on `AVAudioMix`; volume adaptation is an `AVAudioSession` mode, not a volume multiplier). **End-of-episode / end-of-chapter / end-of-queue** timers do **not** fade. User pause, seek, or cancel timer cancels the fade and restores volume. **Honest:** soft player volume only — **not** equal-loudness / ReplayGain / Skip Silence DSP; may sound coarse with stock `AVPlayer`. Android always fades (no off-toggle); iOS default on allows opt-out.

**Honest:** Soft **software gain** only. Values above 100% **may clip or distort**. This is **not** ReplayGain, loudness normalization, or Android `LoudnessEnhancer`. Apple documents mix volume in 0…1; this beta uses factors up to 3.0 intentionally for modest boost. Some streams (notably **HLS**) may ignore `audioMix` — boost then has no effect for that item. A true DSP loudness pipeline would need `AVAudioEngine` / `MTAudioProcessingTap` and would break the shared video / Now Playing path — this beta does **not** fake that.

## Mobile / Wi‑Fi policy

Settings → **Network / Downloads** (shared `NWPathMonitor` via `NetworkPathGate`):

| Preference | Default | Behavior |
|------------|---------|----------|
| **Current network** (status) | live | Shows Wi‑Fi / Ethernet / Cellular / Offline / Other from the system path monitor. Honesty only — **no** VPN or proxy detection. |
| **Auto-download Wi‑Fi only** (`autoDownloadWifiOnly`) | on | **Auto** enqueue after refresh skipped on cellular / when path unsatisfied. Does **not** block manual downloads. |
| **Manual download Wi‑Fi only** (`manualDownloadWifiOnly`) | off | User-initiated Download buttons refused on cellular; error recorded (`lastError` + download-errors log). Default off = manual may use mobile data. |
| **Stream Wi‑Fi only** (`streamWifiOnly`) | off | `PlaybackService` refuses network stream URLs on cellular; local offline files still play; honest alert (“Cannot stream”) |

Wi‑Fi / Ethernet satisfy Wi‑Fi-only gates; cellular does not. Turn a toggle off to allow cellular for that action. Auto / manual / stream are gated **separately**.

## Max downloaded episodes (episode cache)

Settings → **Downloads / Storage → Max downloaded episodes**. Cap how many **completed** offline downloads to keep (`downloadEpisodeCacheLimit`, picker **Unlimited** (default) / **25** / **50** / **100** / **200** / **500**, UserDefaults + iOS JSON backup). When the completed catalog exceeds the cap, `DownloadService.enforceEpisodeCacheLimit` deletes eligible local files only:

1. **Played** + not favorited + not queued — oldest file mtime first.
2. **Unplayed** + not favorited + not queued — oldest mtime first.
3. **Favorites** and **queued** episodes are **never** auto-deleted by this cap; if only those remain over the limit, eviction stops.
4. The episode that just finished downloading is kept when choosing victims.

Runs after each successful download, when opening Settings (changing the picker), and on app launch / backup reload. **Separate from** Max storage (byte budget): byte eviction still prefers played then unplayed by mtime and does **not** skip favorites/queue. EN/DE + VoiceOver.

## Parallel downloads

Settings → **Downloads / Storage → Parallel downloads**. Cap concurrent active episode downloads (`maxParallelDownloads`, picker **1–5**, default **3**, UserDefaults + iOS JSON backup). `DownloadService` only starts that many background `URLSession` tasks at once; further enqueues wait in an in-memory FIFO until a slot frees (per-episode Cancel removes waiting or active; Downloads toolbar **Cancel all downloads** clears **all** active tasks + the waiting FIFO without deleting completed files). **Honesty:** waiting items are session-scoped (not written to disk) — process death drops them; already-started tasks continue via `pending-downloads.json` / background session. Lowering the cap does not cancel in-flight transfers. Manual Wi‑Fi-only is re-checked when a waiting item starts. EN/DE + VoiceOver.

## Unsubscribe

**Subscriptions** trailing swipe and **Feed detail** ⋯ menu both open a destructive **Unsubscribe?** confirmation that includes the podcast title and an honesty line: removes the feed from Subscriptions, per-feed settings (`feed-settings.json`), tags (`feed-tags.json`), queue items from that feed, and favorites / archive / bookmarks / episode private notes / playback-history entries for its episodes (**existing AntennaPod-like feed-scoped cleanup** — not a global Clear queue / Clear favorites / Clear history).

**Downloads on unsubscribe (honest choice):**
- **Unsubscribe** — keeps this feed’s offline files in the Downloads catalog (default).
- **Unsubscribe and delete N downloads (~size)** — shown only when `DownloadService.downloads(forFeed:)` is non-empty; calls `deleteDownloads(forFeed:)` **before** `PodcastStore.unsubscribe`. Removes **only** completed offline files whose episode ids are on this feed’s current catalog (including favorited / starred downloads for those episodes), cancels in-flight downloads for those ids, and does **not** touch other podcasts’ downloads, Delete all downloads, or Delete played downloads. Count + approximate on-disk size (`DownloadStorageUsage.formatBytes`) appear in the button and message when known (missing files contribute 0).
- **Queue / favorites after unsubscribe:** queue entries and stars for this feed’s episodes are still removed by `unsubscribe` itself (same as before this option). The delete-downloads action only removes **files**; it does not keep queue rows for streaming after unsubscribe (episodes leave the library with the feed). Prefer AntennaPod-like: unsubscribing drops feed-scoped library state; optional file cleanup is separate.
- **Local-folder feeds:** unsubscribe still releases the security-scoped bookmark; folder `file://` episodes are usually **not** in the Downloads catalog (already local outside `Documents/downloads`), so the delete-downloads action often shows no extra files.

Confirm on Feed detail then `dismiss()` so the detail pops. Swipe does **not** allow full-swipe (deliberate tap → confirm). EN/DE + VoiceOver hint on the Unsubscribe controls.


**Honest limits:** no RSS/Atom; no network feed refresh; not pushed to gpodder / Nextcloud; omitted from OPML and HTML export. Shown in **Subscriptions** with a **Folder** badge. Bookmarks in JSON backup may not work on another device — re-pick the folder after import.

- **Manage tags (global):** **Settings → Library → Manage tags** and **Subscriptions** toolbar (tag icon) → `ManageTagsView`: lists every in-use tag with **podcast counts**; **`.searchable`** over tag **names** (light debounce ~250 ms; empty query = full list; empty state when no matches — **client-side filter of existing tags only**, no remote tag directory); **Rename** (alert; updates all feeds using that name via `PodcastStore.renameTag`); **Delete** (confirmation dialog; `deleteTag` strips the label from feeds — **does not unsubscribe** or delete downloads). Rename/delete stay on **visible** rows and still apply to that **name across all feeds** (not a filtered subset of podcasts); there is no bulk “delete all tags”. Empty state explains how to add tags. EN/DE + VoiceOver labels/hints.
- **Subscriptions list:** when any tags exist **or** any feed is Keep-at-top / pinned, filter chips (**All** / **Pinned** when any pinned / each tag / **Untagged**) plus optional **Group by tag** (All only — Pinned and other non-All chips stay flat): sections per tag then Untagged; a podcast with several tags appears under each. With grouping off, tag names show as a subtitle on rows. Each row shows a trailing **unplayed badge** (`!isPlayed && !isArchived`, same spirit as Inbox / Feed detail Unplayed) when the count is > 0, plus **per-feed remaining** (`Hh Mm left` / `~…`) under the badge when there is at least one unplayed episode with known duration (hidden when unplayed is 0 or all durations unknown); VoiceOver includes count and remaining when shown. Counts + remaining come from one store pass `PodcastStore.unplayedRemainingByFeedId()` over stored `feed.episodes` (not the All Episodes newest-500 soft cap; RSS window honesty applies). **Remaining time** info bar (`N unplayed • Hh Mm left`) sums the same per-feed summaries over **visible** podcasts only (`tagFilteredFeeds` after search + category + language + tag — **unique** feeds so multi-tag grouping does not double-count); **no** episode preview rows; **not** Inbox tab remaining / All Episodes soft-cap; unknown durations omitted (`~`); live position for the current episode; wall-clock by default; optional Remaining time respects speed ÷ feed/default ≥0.5; **played** (not current) → 0. EN/DE + VoiceOver (filter-scope note on the list bar when search/category/language/tag active).
- **Search:** `.searchable` (prompt **Search subscriptions**, ~250 ms debounce) filters by feed **title**, optional **`descriptionText`**, optional **`author`**, optional **`language`**, and optional **`categories`** (`PodcastStore.matchingFeeds`). Empty query shows the full list under the current sort; empty state when nothing matches (separate copy when category, language, **Pinned**, or tag filter empties the list — **No pinned podcasts** for the Pinned chip). Author / language / categories caption on rows when the feed provides them (localized language name or raw code; `itunes:category` text only; hide when missing). **Explicit** capsule on the title row when channel `itunes:explicit` marks the feed (hide otherwise; VoiceOver includes it).
- **Category filter:** when any stored feed has `itunes:category` text, a **Categories** chip row (**All** + unique library categories only — **never invent** taxonomy). Pipeline: search → category → **language** → tag (AND). Feeds with **empty** categories match **All** only. Pref `AppSettings.subscriptionsCategoryFilter` (UserDefaults + backup; empty = All). Drop selected chip if that category disappears after refresh/unsubscribe.
- **Language filter:** when any stored feed has a language code (`itunes:language` / RSS `language` / `xml:lang`), a **Languages** chip row (**All** + unique library codes only — **never invent** taxonomy). Chip labels use localized `displayLanguage` (or raw code). Pipeline: search → category → language → tag (AND). Feeds with **empty** language match **All** only. Pref `AppSettings.subscriptionsLanguageFilter` (UserDefaults + backup; empty = All; stores code). Drop selected chip if that language disappears after refresh/unsubscribe. Empty state + remaining/unplayed scoped to visible feeds. EN/DE + VoiceOver.
- **Sort:** toolbar menu (**Sort**) — **Recently updated** (default; newest episode `pubDateEpochMs`, same proxy as Home), **Alphabetical A–Z** by feed title, **Author A–Z** by feed-provided author (**missing authors last**; title tiebreak), **Language A–Z** by localized language name / raw code (**missing language last**; title tiebreak), **Most unplayed** (descending per-feed unplayed count — `!isPlayed && !isArchived`, same as badges / Inbox / `unplayedCountsByFeedId`; title tiebreak; full stored feed catalog), **Recently refreshed** (newest successful network `lastRefreshedAtEpochMs` first), or **Least recently refreshed** (oldest stamp first). Refreshed modes: **nil / local-folder last** — never invent timestamps; title tiebreak. Persisted in `AppSettings.subscriptionsSort` (+ JSON backup). Applied after search/category/language/tag filters; when grouping by tag, feeds inside each section use the same order. After the chosen sort, **Keep at top** (`FeedSettings.isPinned`) partitions **pinned first** (stable among pinned / unpinned) — local preference only; **not** a new Picker case; not gpodder. **Client-side only** — no drag-reorder of subscriptions in this beta; never invents author/language/refresh times.
- **Lifecycle:** tags exist only while assigned; removing the last use (or Delete on Manage tags) drops the name from `allTags`.

## Skip intervals (Rewind / Fast-forward)

Settings → **Playback → Rewind** / **Fast-forward**: presets **5 / 10 / 15 / 20 / 30 / 60** seconds plus **Custom…** (5–60 seconds sheet; TextField + Stepper) (`AppSettings.rewindSeconds` / `fastForwardSeconds`, UserDefaults + backup). Defaults match AntennaPod Android (`prefRewindSecs` = 10, `prefFastForwardSecs` = 30). Mini player, full player, Lockscreen / Now Playing remotes, Siri/Shortcuts skip, and `antennapod://skip-*` deep links all use these values (SF Symbol icons update when a numbered glyph exists — e.g. 10/30; otherwise plain `gobackward` / `goforward`). Changing the pickers or Custom… refreshes `MPRemoteCommandCenter` preferred intervals immediately via `RootTabView` `onChange`.

## Skip intro / Skip outro

Settings → **Playback → Skip intro** / **Skip outro**: presets **0 / 5 / 10 / 15 / 30 / 60** seconds (`AppSettings.skipIntroSeconds` / `skipOutroSeconds`, UserDefaults; **0 = Off**). On a **fresh start** (resume position ≈ 0), playback seeks forward by skip-intro once per episode play session. When duration is known and **remaining ≤ skip-outro**, `PlaybackService` treats the episode as finished once (mark played + continuous next (per Continuous playback mode), same path as natural end) — guarded so it does not loop. Resume from mid-episode does not re-apply skip intro. **Per-feed override** (Feed detail → gear → Playback): Use global / Off / same presets; when set, that podcast’s episodes use the override instead of Settings.

## Prefer stream vs download

Settings → **Playback → Playback source**: **Prefer download** (local file via `DownloadService.localURL` when present), **Prefer stream** (always the episode network URL even if downloaded), or **Automatic** (default: local if the file exists, else stream). `PlaybackService.play` and continuous auto-next honor this; EpisodeRow / Downloads play buttons no longer force a local URL. Mini player and full player show a small **Local** / **Stream** indicator for the active item.

## Auto-delete after playing

Settings → **Downloads / Storage → Delete episode after playing** (default off, `AppSettings.autoDeleteAfterPlaying`). **Per-feed** (Feed detail → gear → Downloads → **Delete after playing**): **Use global** / **Always** / **Never** in `feed-settings.json` (`FeedSettings.autoDeleteAfterPlaying`). Always deletes this podcast’s offline file on mark played even when the global toggle is off; Never keeps files even when global is on. Orphan episodes (no owning feed) follow the global toggle only. When allowed, marking played — manual toggle or playback finished / continuous auto-next (`PlaybackService` → `PodcastStore.markPlayed`) — deletes via `DownloadService.delete` if a local file exists. The feed episode row and `isPlayed` status stay. Deletion is deferred while that episode is still the active player item **and** playing from a local file (`shouldBlockAutoDelete`); `PlaybackService` flushes the pending delete on end / stop / switch. **Favorited / starred episodes are skipped** (offline file kept) even when Always is set. Starring while a delete is pending cancels it. Manual Delete download / Delete played downloads / Clear all are unchanged. Storage-limit eviction is unchanged.


## Notifications (Settings honesty)

Settings → **Notifications** lists only what this beta can actually deliver as **local** `UserNotifications` (shared OS permission):

| Toggle | Default | Behavior |
|--------|---------|----------|
| Notify on new episodes | **off** | After feed refresh finds new episode IDs (existing subscriptions) |
| Notify on download errors | on | Download **failures** only |
| Notify on download complete | **off** | Successful download finish (quieter opt-in) |
| Notify on sync errors | on | gpodder / Nextcloud login or sync failures |
| Notify when sleep timer ends | on | Clock / end-of-episode / end-of-chapter / end-of-queue expiry |

**Permission** row shows Allowed / Denied / Not determined / Unknown (EN/DE). When **Denied**, **Open iOS Settings** opens the system Settings app; toggles may stay on but banners stay off until iOS allows Notifications. Status re-checks when Settings returns to foreground (`scenePhase`).

**Notifies** / **Does not notify** coverage rows spell out honesty: **no** push / APNs / server-side alerts; download-complete banners only when that optional toggle is on (default **off**); new-episode tap → **Inbox** only (no episode-level deep link); needs an in-app refresh, download, sync, or sleep-timer fire — not a remote push.

## Notifications (new episodes)

Settings → **Notifications → Notify on new episodes** (default **off**). Uses `UserNotifications` **locally** only — no APNs / push server. Permission is requested when you enable the toggle, or on the first feed refresh that finds new episodes while the toggle is on and status is still undetermined. Settings shows Allowed / Denied / Not determined; if denied, the preference can stay on but no banners fire until iOS Settings allows Notifications (Open iOS Settings button). Per-feed **Notify on new episodes** (Use global / On / Off) filters which podcasts contribute when the **global** toggle is on — **global is master** (per-feed On does nothing while global is off; per-feed Off silences that podcast when global is on). Feeds with Keep updated → Never are skipped by bulk refresh and therefore never contribute newcomers from Refresh all / interval refresh (single-feed refresh still can). After Inbox pull-to-refresh, Keep updated, or a single podcast refresh, newly appeared episode IDs (existing subscriptions only — not first subscribe) post **one aggregated** local notification per refresh (replaces prior banner): single feed → **title** = feed title, **body** = episode title or **“N new episodes”**; multiple feeds → **title** = “New episodes”, **body** = **“N new episodes”**. Tap opens the **Inbox** tab (best-effort; no episode-level deep link). Stable notification id `new-episodes.aggregate`.

## Download log / errors + notify on failures

Failed downloads are appended to a ring buffer (~50) in Application Support `download-errors.json` (episode id, title, feed title, message, timestamp). `DownloadService.lastError` still drives a red **Last download failed** banner on the **Downloads** tab (episode + feed when known). **Downloads → Errors** toolbar and **Settings → Notifications → Download errors** open the same list with **`.searchable`** over episode title / feed title / error message (light debounce ~250 ms; empty query = full log; empty state when no matches — filters already-persisted entries only). Each row has **Retry**: when the episode is still resolvable in the library with a network media URL (not local-folder `file://`), it removes that log row and calls the existing manual `DownloadService.download(_:)` path (same Wi‑Fi / cellular gates, background `URLSession`, storage eviction — **no** invented retry queue). Disabled while a download for that episode is already in flight, or when the episode is gone / has no downloadable URL. A later failure appends a **new** log entry. **Clear** still wipes the **full** log and banner (not the filtered subset; offline files kept).

Settings → **Notifications → Notify on download errors** (default on) reuses the same `UNUserNotificationCenter` permission path as new-episode alerts. On failure (no media URL, HTTP error, move failure, or task error — not user cancel), if the toggle is on and permission allows, a **local** notification posts: **title** = episode title, **body** = short error. Tap opens the **Downloads** tab. **No push / APNs.** Failures only — success uses the separate **Notify on download complete** toggle.

## Notify on download complete

Settings → **Notifications → Notify on download complete** (default **off** — quieter than errors). Same shared `UNUserNotificationCenter` permission path. After a successful temp→Documents move (`DownloadService.handleMovedDownload` — foreground or background `URLSession` finish), if the toggle is on and permission allows, a **local** notification posts: **title** = episode title, **body** = feed title when known (else “Download complete”). Stable id `download-complete.<episodeId>` (one per episode; replaces prior). Tap opens the **Downloads** tab. **Does not** fire for cancelled or failed downloads (errors keep **Notify on download errors**). **No push / APNs.**

Settings → **Notifications → Notify on sync errors** (default on) shares that same permission path. When gpodder.net / Nextcloud **login** or **sync** fails (`GpodderSyncService` records `lastSyncError`), a **local** notification posts: **title** = “Sync failed”, **body** = short error. Tap opens the **Settings** tab and scrolls to **Sync**. **No push / APNs.**

Settings → **Notifications → Notify when sleep timer ends** (default on) shares that same permission path. When a clock, end-of-episode, end-of-chapter, or end-of-queue sleep timer expires (`PlaybackService.expireSleepTimer`), **one** local notification posts (stable id `sleep-timer.end`): **title** = “Sleep timer ended”; **body** = “Playback paused.” (clock), “End of episode — playback stopped.” (EOE), “End of chapter — playback paused.” (EOC), or “End of queue — playback stopped.” (EOQ). While the app is in the foreground, `UINotificationFeedbackGenerator` also fires a success haptic. **No push / APNs.** No deep link required.

## Discovery

Add podcast sheet (**Subscriptions → +**) has four segments: **Apple**, **Index**, **fyyd**, and **URL**.

**Feed URL / Add by RSS** — Add podcast → **URL** tab: paste an RSS/Atom feed URL → **Preview feed** → Confirm Subscribe (same Preview pipeline as discovery). Input is trimmed; a missing scheme gets **`https://`** when the host looks valid (never invents non-http(s)). **Paste** fills the field only; validation errors show on the URL tab before Preview. If the normalized URL already matches a library subscription (canonical match: http↔https, trailing slash), the URL tab shows **Already subscribed** + **Open feed** instead of inviting a duplicate. Already subscribed on Preview → **Open feed**.

**Add from Clipboard** — when the pasteboard normalizes to an **http**/**https** URL with a host (first non-empty line; scheme-less host/path → https), Add podcast shows **Add from Clipboard** (toolbar on any Add mode + URL-tab section with the detected URL). Tap opens the **same** online Preview → Confirm Subscribe path (`FeedPreviewRequest` / `FeedRepository`); does **not** subscribe on launch or without a tap. Not OPML-from-clipboard. Distinct from **Paste** (field only). Non-normalizable pasteboard text hides Add from Clipboard. Preview/load errors surface on the Preview screen as usual.

**Online feed preview** — discovering a podcast (search / charts) or tapping **Preview** on the Feed URL tab opens a Preview screen that fetches and parses the RSS/Atom via `FeedRepository` (same parser as subscribe; **25s** timeout). Errors distinguish **invalid URL**, **timeout**, **network**, **HTTP status**, and **not an RSS/Atom feed**, with Retry. Shows title, author/artwork when known (discovery hints + feed image), optional language / categories / Explicit when the feed provides them, episode count, and the first **10** episode titles. **Confirm Subscribe** runs `PodcastStore.subscribe(feedUrl:)` on the normalized URL; **Cancel** goes back. If the feed URL is already in the library (canonical match), the primary action is **Open feed** (pushes `FeedDetailView`) instead of Subscribe. Discovery rows are no longer fire-and-forget Subscribe.

**Top lists / Charts** (**Home → Discover** preview, **Subscriptions → Library → Discover**, or See all charts): public Apple iTunes RSS `https://itunes.apple.com/{country}/rss/toppodcasts/limit={N}/explicit=true/json` (no API key). Full Discover / TopListsView **N** comes from **Settings → Discovery → Discover charts count** (`discoverChartsLimit`, presets **10 / 25 / 50 / 100**, default **25**; UserDefaults + iOS JSON backup; always capped — no Unlimited; Apple URL clamp 1…200). Does **not** change Home Discover preview (`homeDiscoverPreviewLimit`), episode-list / Recently updated Home soft-caps, or Podcast Index search. Country defaults to the device region (fallback **de**); override under **Settings → Discovery → Charts country**. Entries are parsed for title / artist / artwork; collection ids are resolved to RSS `feedUrl` via a batch `itunes.apple.com/lookup` call. Pull-to-refresh reloads the list; changing country / charts count / parental explicit filter reloads; network/country errors are shown honestly. Rows open **Preview** (then Confirm Subscribe).

**Apple Podcasts** uses the public iTunes Search API (`media=podcast`, no API key) via `URLSession` (`ItunesSearchService`). Results that include a `feedUrl` are listed with artwork, title, and artist; **Preview** then Confirm Subscribe uses `PodcastStore.subscribe(feedUrl:)` / `FeedRepository`. Search is lightly debounced (~400 ms). Empty results and network/decode errors are surfaced in the Add sheet.

**Podcast Index** (`PodcastIndexSearchService`) calls `https://api.podcastindex.org/api/1.0/search/byterm` with auth headers `X-Auth-Date`, `X-Auth-Key`, and `Authorization` = SHA-1(`apiKey` + `apiSecret` + unix time) per the Podcast Index docs. **API key and secret are user-supplied** (free registration at podcastindex.org) and stored only in the **Keychain** (`PodcastIndexKeychain`) — nothing is hardcoded or shipped with the app. Paste them under **Settings → Discovery / Podcast Index**. If keys are missing, the Add sheet shows an honest empty state explaining how to get keys. Results show title, author, and artwork; **Preview** then Confirm Subscribe. Debounce matches Apple (~400 ms).

**fyyd** (`FyydSearchService`) calls the public fyyd.de API `https://api.fyyd.de/0.2/search/podcast?term=` (optional `count` / `page`). **No API key** for basic search. Results that include `xmlURL` are listed with artwork (`imgURL`), title, and author; **Preview** then Confirm Subscribe. Debounce matches Apple (~400 ms). Empty results and network/decode errors are surfaced honestly in the Add sheet.


## Sync / gpodder.net / Nextcloud

Settings → **Sync** (beta — **subscriptions only**, never full library sync):

- **Provider** picker: **gpodder.net** (default) vs **Nextcloud** (Gpodder Sync app).
- **Host / base URL**
  - gpodder.net: defaults to `https://gpodder.net` (editable).
  - Nextcloud: custom base — server root (`https://cloud.example.com`) or full API root (`https://cloud.example.com/index.php/apps/gpoddersync/`). If the path does not already contain `gpoddersync`, the client appends `index.php/apps/gpoddersync/` (same root AntennaPod Android + [nextcloud-gpodder](https://github.com/thrillfall/nextcloud-gpodder) use).
- **Username** / **password**: password in the **Keychain** only (never plaintext UserDefaults / backup JSON); username + provider + host + device metadata in `UserDefaults`. Nextcloud: prefer an **app password**.
- **Device name** + stable **device id** (gpodder.net API2; Nextcloud has no device API — fields kept for UI/state only; update is a no-op).
- **Login** / **Logout** / **Sync now**; **Last sync** time, status line, and error (red). Login/sync failures can post a **local** notification when Settings → Notify on sync errors is on (tap → Settings Sync).
- **Coverage rows (honesty):** **Synced** = http(s) subscription feed URLs (additive pull/push). **Local only** = episode actions (play/download/position), queue, favorites, bookmarks, episode private notes, tags, downloads, local folder feeds, playback progress, archive, inbox.

Client (`GpodderClient`, `URLSession`, HTTP Basic), reused for both providers:

**gpodder.net** ([API reference](https://gpoddernet.readthedocs.io/en/latest/api/reference/)):

- `POST /api/2/auth/{username}/login.json`
- `POST /api/2/devices/{username}/{deviceid}.json`
- `GET /api/2/subscriptions/{username}/{deviceid}.json?since=`
- `POST /api/2/subscriptions/{username}/{deviceid}.json` with `{ "add", "remove" }`

**Nextcloud** (API root `…/index.php/apps/gpoddersync/`):

- Login probes `GET …/subscriptions?since=0` (no dedicated auth/device endpoints).
- `GET …/subscriptions?since=`
- `POST …/subscription_change/create` with `{ "add", "remove" }`

**Sync behavior (both):** pull remote adds → `subscribeQuietly` for missing feeds; push local **http(s)** URLs not on the server (`local-folder://` and non-http feeds omitted). **Additive merge:** remote `remove` does **not** unsubscribe local podcasts. Status is always framed as **Subscriptions sync (partial)** — episode actions / queue / bookmarks / episode private notes / tags / downloads stay **local-only**. Same limits for Nextcloud as gpodder.net.

## Data backup (iOS JSON)

Settings → **Backup** (beta):

- **Include downloaded episode files** — toggle (default **off**). Off = catalog-only JSON ZIP (small/fast). On = also pack Documents/downloads into ZIP folder `downloads/` (STORE / no compression); UI shows approximate file count + size and a confirmation when exporting with media (can be large/slow).
- **Export data backup** — builds a ZIP (`AntennaPod-iOS-Backup-….zip`) with `manifest.json` (`includesMedia` flag), Application Support maps (`feeds`, `queue`, `playback`, `downloads` catalog, `feed-settings`, `favorites`, `archived`, `bookmarks`, `episode-notes`, `feed-tags`, `download-errors`, `local-folder-bookmarks`), `app-settings.json`, `gpodder-prefs.json`, and optionally `downloads/<fileName>` media. Share via the system sheet.
- **Import data backup** — file importer (`.zip`) → confirmation **Replace local data?** → restore JSON maps + prefs → if present, write ZIP `downloads/*` into Documents/downloads (merge: overwrite same names, leave other local files) → refresh store / downloads catalog (pruned to media present on device) / Settings / gpodder.
- **Honesty:** iOS JSON Application Support backup — **not** Android AntennaPod database export. Media is **optional** (default omitted). **No Keychain secrets** (re-enter gpodder password / Podcast Index keys on a new device; same-device Keychain may still unlock login). HTML subscription list is **Export subscriptions as HTML** under Import / Export (not this ZIP).

## OPML

Export writes AntennaPod-compatible OPML 2.0 (`outline` with `text`/`title`/`xmlUrl`/`htmlUrl`) via the system **share sheet** or **Save OPML to Files…** (`fileExporter`). Local folder feeds are omitted.
